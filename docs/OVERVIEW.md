# KSA 무선국 정기검사 관리 시스템 — 개요

> **이 문서의 용도**
> 지역본부 실무자가 본부장(상급자)에게 우리가 사용하는 무선국 정기검사 관리 시스템을 설명·보고할 때 참고할 수 있도록 정리한 자료입니다.
> 기능 단위로 "왜 만들었는지 / 무엇이 어떻게 바뀌었는지 / 누가 언제 사용하는지"를 위주로 기술합니다. 기술적인 코드/내부 구조는 [PRD.md](PRD.md), [docs/rules/](rules/)를 참조하세요.

---

## 1. 한 줄 요약

> **연간 무선국 정기검사 일정 등록부터 현장 수검 완료까지, 세 팀이 같은 시스템 안에서 논스톱으로 협업하도록 만든 통합 관리 시스템.**

---

## 2. 도입 배경 — 무엇이 문제였는가

### 기존 방식 (As-is)

```
수검대상 공지 → 수검대상 검토 → 서류 현행화 / 성능 점검
            → 현장 실사·수정 → 수검 서류 작성 → 수검
```

- **6단계 워크플로우**가 팀 간 인계마다 **엑셀 핸드오프 3회 이상** 발생
- 각 팀이 다른 양식의 엑셀을 주고받으며 **데이터 일관성 확보 어려움**
- 현재 어느 단계까지 진행됐는지 **눈으로 일일이 확인**해야 했음
- 변경개설(허가사항 변경 신고)이 필요한 건은 **별도 수기 처리**

### 새 방식 (To-be)

- 무선국 수검 관리 시스템 **한 곳**에서 수검 일정 및 현황을 관리
- N/W계획팀 / N/W혁신팀 / 품질개선팀이 **같은 시스템을 보며 협업**
- 변경개설 신고처럼 분기 작업도 **시스템 내에서 논스톱 처리**
- 현재 단계 / 누가 액션을 취해야 하는지 / 지연된 건은 어디인지 **한눈에 확인**

## 3. 액터(역할)와 책임

| 액터 | 시스템 권한 | 주요 행위 | 빈도 |
|------|-------------|----------|------|
| **N/W계획팀** | (관리자) | 연간 수검대상 엑셀 업로드 (전파관리소 → 우리 시스템) | 연 1회 |
| **N/W혁신팀** | manager (본부 관리자) | 일정 등록, 사전점검 의뢰, 변경개설 신고, 검사내역서 발급, 전파관리소 접수 | 상시 |
| **품질개선팀** | member (일반 사용자) | 전산비교 수행, 변경개설 작성, 현장 수검 | 상시 |

| **시스템 관리자** | admin | 전사 조회, 사용자 권한 관리, 데이터 보정 | — |

## 4. 핵심 워크플로우 — 한 건의 무선국이 거치는 길

```
[등록됨] ─ 혁신팀이 일정 등록
   │
   ├── 1) 정상 흐름 (사전점검 진행) ────────────┐
   │   "사전점검 의뢰" → [사전점검중]            │
   │   품개팀 전산비교 → [점검완료]              │
   │                                            │
   ├── 2) 변경개설 분기 ──────────────────────┤
   │   품개팀 "변경개설 필요"                    │
   │   → [변경개설중] → 혁신팀이 전파관리소 신고 │
   │   → [재점검 대기] → 부분 DS 회신            │
   │   → 자동 재비교 → [점검완료]                │
   │                                            │
   └── 3) 사전점검 스킵 분기 ────────────────────┘
       혁신팀이 서류·성능만으로 분류 완료
       → 바로 [검사내역서 발급]

[점검완료 또는 등록됨]
   ↓ 혁신팀 "검사내역서 발급"
[검사내역서 발급]
   ↓ 혁신팀 전파관리소 접수 후 접수번호 입력
[접수완료]
   ↓ 품개팀 현장 수검 + 결과 입력
[수검완료]
   └─ 합격이 아니면 "재점검 필요" 플래그 자동 표시
```

각 단계는 시스템에 **배지(색상 라벨)**로 표시되며, 클릭 한 번으로 해당 상태 건만 모아 볼 수 있습니다.

## 5. 주요 기능 모음

### 5.1 연간 수검대상 관리
- 전파관리소가 제공한 연간 대상 엑셀을 그대로 업로드
- 자동으로 **카카오 좌표 변환 (지오코딩)** — 지도에서 바로 확인 가능
- 본부/팀별 자동 분류, 중복 검증

### 5.2 일정 관리
- 본부/팀/주차/조/검사관 단위로 일정 배정
- **묶음 단위(팀+주차+조)** 일괄 등록·수정·삭제
- 일정 변경 이력이 자동으로 기록되어 감사 추적 가능

### 5.3 전산비교 (사전점검)
- 우리 ERP 데이터 vs 전파관리소 DS 데이터를 자동 비교
- **2가지 항목 비교**: 설치형태 / 일련번호 (장치별)
- 5가지 결과 분류: 일치 / 부분일치 / 불일치 / DS누락 / 확인필요
- 이상 없으면 "이상 없음 회신" 한 번에 점검 완료 처리
- 외부 사이트 확인이 필요한 건은 별도로 표시되어 누락 방지

### 5.4 변경개설 자동화
- 전산비교에서 불일치/DS누락 발견 시 체크박스 하나로 "변경개설 필요" 등록
- **신고서(A파일)가 자동 생성** — 품개팀이 입력한 데이터로 시스템이 만듦
- 묶음 단위로 한 번에 다운로드 (담당자별로 분리되어 깔끔)
- 신고 후 전파관리소가 회신한 부분 DS만 업로드하면 **자동 재비교 후 통과 처리**

### 5.5 검사내역서 발급 + 접수 트래킹
- 점검 완료된 건을 다중 선택 → "검사내역서 발급" 클릭 → 즉시 다운로드
- **사전점검을 거치지 않은 건도 발급 가능** (혁신팀 사전 분류 후 바로 발급하는 케이스 지원)
- 발급 직후 자동으로 "접수번호 일괄 입력" 다이얼로그가 떠서 그 자리에서 처리
- 접수번호를 나중에 입력하고 싶으면 일정 화면에서 다중 선택 후 일괄 입력 가능
- 접수일은 입력 시점으로 자동 기록

### 5.6 현장 수검
- **현장 수검 지도** — 본인 담당 건만 자동 필터링되어 지도 위에 표시
- "수검가능" 토글로 **전파관리소 접수가 완료된 건**만 표시 (도메인 룰: 접수 안 된 건은 수검 불가)
- 안테나 방위각 부채꼴 표시 — LTE 멀티밴드 장비 시각화
- 경로 계획 기능으로 하루 수검 동선 최적화
- Tmap / 카카오내비 딥링크로 모바일 앱에서 바로 길안내

### 5.7 검사 결과 기록
- 합격/불합격/부적합 + 검사일 + 사진 + 메모 입력
- 결과 입력 시 워크플로우가 **자동으로 [수검완료] 단계로 전환**
- 불합격/부적합이면 **"재점검 필요" 플래그가 자동 세팅** → 혁신팀이 재점검 일정 등록 시 식별 가능
- 합격 결과는 INSPECTED 단계부터만 화면에 표시 (진행 중 상태에선 결과 컬럼 숨김)

### 5.8 실적 대시보드
- 전국 9개 본부 진도율 지도 + 본부별 합격율 차트
- 분기별 / 월별 / 주차별 합격율 추이
- 장비 타입별 불합격 분석
- 현황 리포트 자동 생성 (성능/서류 달성 여부)

## 6. "내 할 일" 대시보드 — 역할별 첫 화면

홈 화면에 접속하면 **현재 본인이 처리해야 할 일**이 한눈에 들어오는 대시보드가 표시됩니다.

| 역할 | 표시 범위 | 주요 카드 |
|------|----------|----------|
| **시스템 관리자** | 전사 | 8단계 상태별 카운트 + 전체 지연 건 + 재점검 필요 |
| **본부장** | 자기 본부 | 본부 상태별 카운트 + 본부 지연 건 |
| **실무자** | 자기 본부 + 팀 | 팀 상태별 카운트 + 팀 지연 건 |

### 추가 기능
- **상태 카드 클릭** → 일정 화면으로 이동하면서 해당 상태 건들만 자동 필터링
- **재점검 필요 카드** → 일정 화면에서 재점검 필터가 자동으로 켜진 채 열림
- **지연된 일정 상위 5건**이 미니 리스트로 표시 — 본부장이 한눈에 "어디가 막혔는지" 파악 가능

### SLA (지연 기준)

각 단계가 다음 일수를 초과하면 시스템이 자동으로 "지연"으로 강조합니다:

| 단계 | 임계점 |
|------|--------|
| 사전점검중 | 5일 |
| 변경개설중 | 3일 |
| 재점검 대기 | 7일 |
| 내역서발급 | 3일 (접수번호 미입력) |
| 접수완료 | 14일 (현장 수검 미완료) |

## 7. 알림 시스템

### 시스템 내 알림 (우상단 종 아이콘)
- 다음 단계 담당자에게 **자동 알림** (예: 사전점검 의뢰 → 품개팀, 신고 완료 → 혁신팀)
- 안 읽음 개수가 빨간 배지로 표시 (60초마다 자동 새로고침)
- 클릭하면 안 읽음 / 전체 토글로 알림 패널 확인

### 로그인 자동 팝업
- 안 읽은 알림이 있으면 **로그인 직후 자동으로 알림 팝업**이 떠서 즉시 인지 가능
- "오늘은 더이상 보지 않기" 체크박스 → 그날 하루는 다시 안 뜸

### 자동 알림 트리거 (8종)
| 이벤트 | 받는 사람 |
|--------|----------|
| 사전점검 의뢰됨 | 품개팀 담당자 |
| 사전점검 회신 완료 | 혁신팀 (등록자) |
| 변경개설 작성 요청 | 혁신팀 |
| 전파관리소 신고 완료 | 혁신팀 |
| 부분 DS 자동 적용 완료 | 혁신팀 |
| 검사내역서 발급됨 | 혁신팀 |
| 접수 완료 — 수검 가능 | 품개팀 |
| 수검 완료 | 혁신팀 |

> **현 단계는 시스템 내 알림 전용** — 이메일/SMS/카카오톡/Slack 등 외부 채널 알림은 도입 예정입니다.

## 8. 권한과 보안

### 권한 체계 (3단계)

| 역할 | 영문 | 권한 범위 |
|------|------|----------|
| 시스템 관리자 | admin | 모든 본부, 모든 기능, 사용자 권한 관리 |
| 본부 관리자 | manager | 자기 본부 데이터 + 결과장 업로드 + DS 업로드/삭제 |
| 일반 사용자 | member | 자기 팀 데이터 조회, 현장 수검, 검사 결과 입력 |

### 보안 조치
- 사번 + SSO 인증 (HMAC 토큰, 2시간 유효)
- 본부별 데이터 격리 (다른 본부 데이터 자동 비활성)
- **30일 미접속 시 자동 휴면 처리** — D-7/D-3/D-1 메일 예고 발송 후 차단
- 모든 주요 액션은 감사 로그에 기록 (90일 보존)

## 10. 시스템 구성 (개략)

```
[지역본부 PC/모바일]
        │
        │  HTTPS
        ▼
[프론트엔드] ───── AWS Amplify
   Flutter Web (PC/모바일 동일 화면)
        │
        │  API
        ▼
[백엔드] ───── AWS EC2
   FastAPI (Python)
        │
        ├─ SQLite (수검 일정/결과)
        ├─ DynamoDB (사용자/권한/DS)
        └─ AWS S3 (사진/파일/엑셀)
```

- **PC/모바일 동일 시스템** — 사무실에서 등록·관리, 현장에서 모바일로 수검 결과 입력
- 외부 시스템 (전파관리소)과는 **데이터 입력 슬롯**으로만 연동 — 외부 시스템 변경 영향 최소화

## 12. 자주 묻는 질문 (FAQ)

**Q. 기존에 쓰던 엑셀은 어떻게 되나요?**
- 전파관리소가 보내주는 연간 대상 엑셀과 부분 DS 회신 엑셀은 그대로 시스템에 업로드합니다. 팀 간 핸드오프 엑셀은 없어집니다.

**Q. 다른 본부 데이터를 볼 수 있나요?**
- 일반 사용자는 자기 팀, 본부 관리자(본부장 포지션)는 자기 본부까지만 보입니다. 시스템 관리자만 전사 조회가 가능합니다.

**Q. 현장에서 인터넷이 안 되면 어떻게 하나요?**
- 현재는 온라인 사용을 전제로 합니다. 모바일 데이터 환경에서 동작하며, 추후 오프라인 임시 저장 기능은 검토 대상입니다.

**Q. 사진은 어디 저장되나요?**
- AWS S3 클라우드 스토리지에 안전하게 저장되며, 본인이 입력한 검사 결과 화면에서만 조회 가능합니다.

**Q. 검사내역서 양식은 정해진 양식인가요?**
- 기존 전파관리소에 제출하던 검사내역서와 100% 동일한 엑셀 양식이 자동 생성됩니다. 시트명·셀 폭·테두리까지 동일합니다.

**Q. 누락된 알림이 있으면 어떻게 확인하나요?**
- 우상단 종 아이콘 → 알림 패널에서 "안 읽음만" 필터 해제 시 전체 이력 조회 가능합니다. 또한 시스템 내 알림과 별개로 워크플로우 상태 자체가 일정 화면에 영구 기록됩니다.
